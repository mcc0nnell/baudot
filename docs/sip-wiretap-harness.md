# JAIN SIP + Wiretap harness

Baudot owns accessible real-time communications behavior and test vocabulary. JAIN SIP and Sandia Wiretap are execution adapters: they let Baudot exercise transport behavior without redefining the T.140 semantic core or the canonical test vectors.

## Boundary

```text
Baudot scenario / expectation
        |
        +-- JAIN SIP probe ------------ signaling observation
        |
        +-- UDP media-path probe ------ generic reachability observation
        |
        +-- canonical RFC 4103 vector - primary RTT packet observation
        |
        +-- Wiretap ------------------- controlled routed topology
        |
        `-- evidence aggregation ------ states + preserved hashes
```

The generic UDP heartbeat remains intentionally non-RTP. It exists to prove that SIP signaling and generic media-path reachability are independent observations.

The RFC 4103 runtime slice is separate: it replays an exact canonical primary `text/t140` RTP packet generated by Baudot's Python reference implementation and independently validates the packet received by the Java runtime. That is a narrow primary-packet transport proof, not a complete RFC 4103 implementation or conformance claim.

## Distributed roles

`BaudotProbe` has two roles, selected with `BAUDOT_ROLE`:

- `callee`: binds the SIP endpoint and generic media receiver, answers INVITE, records INVITE/ACK state, and preserves what arrived.
- `caller`: sends INVITE, completes the dialog on 200 OK, sends the generic media probe when enabled, and records what it sent.

Both sides use the same `BAUDOT_CORRELATION` value. `EvidenceAggregator` verifies the role manifests, joins the two role bundles, and keeps scenario success distinct from the observed communications state.

The RFC 4103 runtime probe is gated on an established SIP dialog. It does not treat RTT transport receipt as proof that SIP negotiated RTT.

## Aggregate state

The aggregate deliberately separates call, media, and RTT observations.

Baseline routed signaling + media:

```text
scenarioResult=PASS
callState=CALL_ESTABLISHED
mediaState=MEDIA_RECEIVED
```

Injected media failure:

```text
scenarioResult=PASS
callState=CALL_ESTABLISHED
mediaState=MEDIA_FAILED
```

Canonical RFC 4103 primary runtime proof:

```text
scenarioResult=PASS
callState=CALL_ESTABLISHED
mediaState=MEDIA_FAILED
rttState=RTT_RECEIVED
sdpNegotiated=false
```

The second result proves signaling can remain healthy while the generic media path is unavailable. The third adds a separately routed RTT path and proves receipt of one canonical primary `text/t140` RTP packet while preserving the generic media failure.

`RTT_RECEIVED` is not `RTT_READY`. Baudot's portable readiness contract still requires RTT negotiation plus the first T.140 character observation. Scenario 003 deliberately records `sdpNegotiated=false`, so it cannot be used to claim end-to-end RTT readiness or full RFC 4103 interoperation.

## Local deterministic smoke runs

The checked-in loopback scenarios exercise evidence/classification without Wiretap:

```bash
bash scripts/run-local-scenario.sh scenarios/001-signaling-and-media.env
bash scripts/run-local-scenario.sh scenarios/002-signaling-only.env
```

Scenario 002 uses a deliberately unavailable local media target. It is a synthetic negative control, not a NAT, SBC, browser, or production-network claim.

## Routed Wiretap lab

The hosted routed lab places caller and callee in separate Linux network namespaces. The host provides only the test underlay; Wiretap carries the selected routed prefixes.

The current logical planes are:

```text
198.18.0.0/24   Wiretap test underlay
10.77.10.0/24   SIP signaling
10.77.20.0/24   generic media reachability
10.77.30.0/24   RTT / canonical RFC 4103 primary packet
```

Wiretap's own reserved API prefixes are kept out of the underlay. The workflow pins Sandia Wiretap v0.9.0 and verifies the downloaded release archive against the published checksum before executing it.

SIP uses RFC 3581 `rport`. The caller binds to its Wiretap E2EE identity, the callee observes the actual UDP source tuple, and the 200 OK returns over the same transparent UDP flow. No reverse-expose shim is required.

The routed scenarios currently exercise:

```text
001-wiretap-routed
  Wiretap routes: signaling + media
  Expected: CALL_ESTABLISHED / MEDIA_RECEIVED

002-wiretap-routed
  Wiretap routes: signaling only
  Expected: CALL_ESTABLISHED / MEDIA_FAILED

003-rfc4103-primary-routed
  Wiretap routes: signaling + RTT
  Generic media route withheld
  Expected: CALL_ESTABLISHED / MEDIA_FAILED / RTT_RECEIVED
```

## Canonical RFC 4103 runtime binding

The canonical primary RTP suite lives at:

```text
testkit/rfc4103/primary-rtp-v1.json
```

`baudot_reference.rfc4103.PrimaryT140RtpPacket` is the authoritative construction/parse reference for that suite. The runtime materializer selects a vector, recomputes the packet from its declared fields, compares it byte-for-byte with the suite's `packetHex`, and emits:

```text
packet.bin
vector.properties
```

The Java runtime adapter does **not** serialize a second version of the packet. It sends the canonical `packet.bin` and independently parses the bytes observed at the receiver. It validates:

- RTP version 2 fixed-header constraints;
- payload type;
- sequence number;
- timestamp;
- SSRC;
- marker bit;
- exact T140block bytes;
- strict UTF-8 validity; and
- packet SHA-256.

The current routed proof uses `BAUDOT-RFC4103-PRIMARY-001 / multibyte-primary-block`, whose T140block is the UTF-8 encoding of `café`.

## Evidence bundle

Each SIP role emits:

```text
<evidence-root>/<scenario>/<correlation>/<role>/
  events.jsonl
  result.properties
  manifest.sha256
```

Aggregation adds:

```text
<evidence-root>/<scenario>/<correlation>/aggregate/
  result.json
  manifest.sha256
```

Routed runs additionally preserve topology and Wiretap observations. Scenario 003 also preserves the canonical vector materialization and RTT runtime results. The outer bundle manifest covers the files needed to reconstruct the proof, including route tables, sanitized Wiretap status/log output, role manifests, aggregate state, vector metadata, canonical packet bytes, and RTT sender/receiver evidence.

Wiretap private-key material is redacted from preserved/debug logs.

This is evidence preservation, not attestation. Signing, provenance, and WindAnvil policy evaluation are separate layers.

## Claim boundary

The current routed evidence supports these narrow statements:

- a SIP `INVITE -> 200 -> ACK` dialog can be established across the Wiretap fixture;
- signaling and generic media reachability can diverge in a controlled routed topology;
- a canonical non-redundant primary `text/t140` RTP packet can cross a separately routed Wiretap RTT path and be independently validated at the receiver.

It does **not** establish complete RFC 4103 or T.140 conformance. In particular, the current runtime proof defers:

- SDP `text/t140` payload negotiation;
- RFC 2198 redundancy;
- packet-loss recovery and reordering behavior;
- RTCP;
- T.140/RFC 4103 buffering and timing profile behavior;
- complete presentation behavior;
- NAT/SBC, browser, production-network, or accessibility conformance.

## Dependency posture

The signaling harness uses `javax.sip:jain-sip-ri:1.3.0-91`. The RI is old, so Baudot treats it as a bounded interoperability instrument rather than a general-purpose platform choice. Its legacy Log4j 1.x API is bridged to SLF4J instead of adding a Log4j 1.x runtime dependency.

Wiretap remains an external executable and topology provider. Baudot does not vendor it or make Wiretap's network model part of Baudot's semantic core.
